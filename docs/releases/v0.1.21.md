> 基于上游 TransitHub `v0.1.15`，移植上游 `v1.0.0`—`v1.1.0` 的部分修复 · Linux amd64 镜像

支持新版 New API 的登录与自动续期，保存的登录凭据可加密存储，并修复上游 Key 列表不全、New API 自有站营收统计不全等问题。

### 新增
- **凭据加密**：设置 `CREDENTIAL_ENCRYPTION_KEY` 后，站点会话、上游登录状态、对接记录中的上游 Key 和通知机器人密钥加密保存。
- **新版 New API 登录**：支持新版 New API 的账号密码登录与自动续期，以及个人访问令牌（`nap_` 开头）。

### 变更
- **访问令牌登录**：New API 的用户 ID 改为可选，留空时自动识别；账号开启两步验证或旧版令牌缺少用户 ID 时给出对应提示。
- **用户列表接口**：移除会向任意已登录账号返回全部账号邮箱的 `GET /api/users`。

### 修复
- 修复上游 API Key 超过 100 个时，对接和绑定找不到较早创建的 Key 的问题。
- 修复 New API 自有站的营收和分组用量只统计管理员本人消费的问题。
- 修复 Sub2API 账号导出凭据缺少上游地址时，分组健康无法探活的问题。
- 修复更新管理员凭证时校验失败会丢失已刷新的令牌、需要重新登录的问题。
- 修复数据库表不在 `public` schema 时兼容迁移被跳过的问题。

### 升级说明
- 从 `v0.1.20` 升级只需替换应用容器，本版没有数据库结构变更，原有数据保留。
- 未设置 `CREDENTIAL_ENCRYPTION_KEY` 且 `/app/data` 不是持久卷时，凭据继续明文保存，与上一版相同。
- 启用加密：用 `openssl rand -base64 32` 生成密钥，写入应用容器的环境变量；密钥需与数据库备份一起长期保存，丢失后已保存的登录需重新填写。
- 启用加密后，应用启动约 1 分钟时把已有的明文凭据改为加密保存。
- New API 自有站的营收与分组用量自升级后按全站统计，已结算的历史数据不重算。
- 回滚：切回保存的旧应用镜像，不需要恢复数据库；启用过加密时，回滚到 `v0.1.20` 后需重新登录我的站点和各上游站点，并重新填写通知机器人配置。

### 安装
```bash
sha256sum -c SHA256SUMS
docker load -i transithub-v0.1.21-linux-amd64.tar.gz
```

- 导入后镜像名为 `transit-hub:v0.1.21`；已有部署先备份配置、数据库、Redis 和附件，再只替换应用容器。
- 其他架构按 [README](https://github.com/gwen-liu/transit-hub/blob/main/README_CN.md#部署) 从源码构建。

### 已知问题
- 更换 `CREDENTIAL_ENCRYPTION_KEY` 后，已加密的凭据无法读取，需要重新登录和填写。
- 7 天以前成本日结未完成的日子不自动重算，按已有记录显示。
- 对接、倍率写入和活动执行使用进程内锁，多实例部署时不跨实例生效。
- New API 上游的令牌已被删除时，“完全解除”重试仍会报错。
- 活动开启过程中服务中断，活动停在执行中，需要手动处理；活动预览中原倍率未知时显示为 0。
