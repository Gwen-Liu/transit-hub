> 基于上游 TransitHub `v0.1.15` · Linux amd64 镜像

修复 Sub2API 上游 Grok 等分组无法自动对接的问题，并重算最近 7 天内成本日结未完成的日子。

### 新增
- **Grok 协议**：自动创建资源时可选择 Grok；New API 上游中 xAI 厂商的分组推荐 Grok 平台的自有分组。

### 修复
- 修复对接 Sub2API 上游的 Grok、Kimi 等平台分组时，不能自动识别协议、也不筛选同平台自有分组的问题。
- 修复成本日结失败后，前几日只保留偏低的日内采样、利润率偏离正常范围的问题。

### 升级说明
- 从 `v0.1.19` 升级只需替换应用容器，本版没有数据库结构变更；从更早版本升级时，启动时自动完成 `v0.1.19` 的结构迁移，原有数据保留。
- 升级后，最近 7 天内成本日结未完成的日子按当日上游实际消费 × 当前充值倍率重算，期间改过充值倍率的日子同样按当前倍率计算。
- 回滚：切回保存的旧应用镜像，旧版本忽略新增列，不需要恢复数据库。

### 安装
```bash
sha256sum -c SHA256SUMS
docker load -i transithub-v0.1.20-linux-amd64.tar.gz
```

- 导入后镜像名为 `transit-hub:v0.1.20`；已有部署先备份配置、数据库、Redis 和附件，再只替换应用容器。
- 其他架构按 [README](https://github.com/gwen-liu/transit-hub/blob/main/README_CN.md#部署) 从源码构建。

### 已知问题
- 7 天以前成本日结未完成的日子不自动重算，按已有记录显示。
- 对接、倍率写入和活动执行使用进程内锁，多实例部署时不跨实例生效。
- New API 上游的令牌已被删除时，“完全解除”重试仍会报错。
- 活动开启过程中服务中断，活动停在执行中，需要手动处理；活动预览中原倍率未知时显示为 0。
